# Дедупликация каталога

Маркетплейс собирает каталог товаров из нескольких источников, и один и тот
же товар приходит в разном написании. Нужно хранить множество **уникальных**
товаров и отвечать на запросы к нему.

Товар — это пара:

- `name` — название из латинских букв и цифр, **регистр не важен**
  (`Apple` = `APPLE`);
- `tags` — **множество** целых чисел, **порядок не важен**
  (`[1, 2]` = `[2, 1]`), повторов внутри одного товара нет, может быть пустым.

Два товара совпадают, если совпадают и название (без учёта регистра), и
множество тегов.

## Операции

| Код | Операция | Ответ |
|---|---|---|
| `A` | добавить товар | `+`, если товар новый; `-`, если такой уже был |
| `H` | проверить наличие | `+`, если есть; `-`, если нет |
| `R` | удалить товар | `+`, если товар был и удалён; `-`, если его не было |

## Формат

**Вход** — одна JSON-строка в stdin:

```json
{"ops": "AHR...", "names": ["...", ...], "tags": [[...], ...]}
```

`i`-я операция — это `ops[i]` над товаром `(names[i], tags[i])`.

**Выход** — одна JSON-строка в stdout: строка из `+`/`-` длины `n`.

## Ограничения

| Параметр | Значение |
|---|---|
| Количество операций `n` | 1 ≤ n ≤ 10⁵ |
| Длина названия | 1…20 символов `[A-Za-z0-9]` |
| Тегов у одного товара | 0…20 |
| Суммарно тегов во входе | ≤ 10⁶ |
| Значение тега | 0 ≤ v < 2³¹ |
| Время работы | C++ / Rust / Zig — 1 с, Go — 2 с, Python — 5 с |

## Пример

```json
{"ops": "AAHHAHARH",
 "names": ["Apple", "apple", "APPLE", "apple", "Pear", "pear", "Apple", "APPLE", "apple"],
 "tags": [[1, 2], [2, 1], [1, 2], [1], [], [], [3], [2, 1], [1, 2]]}
```

```json
"+-+-++++-"
```

| # | Операция | Ответ | Почему |
|---|---|---|---|
| 1 | A Apple {1,2} | `+` | новый |
| 2 | A apple {2,1} | `-` | тот же товар: регистр и порядок тегов не важны |
| 3 | H APPLE {1,2} | `+` | есть |
| 4 | H apple {1} | `-` | другое множество тегов |
| 5 | A Pear {} | `+` | новый, пустое множество тегов допустимо |
| 6 | H pear {} | `+` | есть |
| 7 | A Apple {3} | `+` | название то же, теги другие: это другой товар |
| 8 | R APPLE {2,1} | `+` | удалили товар №1 |
| 9 | H apple {1,2} | `-` | его больше нет |

## Главное требование

Товар — это **ваш собственный тип** (struct / class) с **вручную написанными**
хэш-функцией и сравнением на равенство. Нельзя склеивать товар в строку
(`"apple|1,2"`) и класть в стандартную хэш-таблицу эту строку: вся суть
задачи — научить хэш-таблицу работать с пользовательским типом (лекция 2,
слайд «Использование пользовательских типов»).

Хэш должен быть:

1. **согласован с равенством**: равные товары всегда дают равный хэш;
2. **не зависеть от порядка тегов** и регистра названия;
3. **хорошо перемешивать**: закрытые тесты содержат тысячи товаров, которые
   отличаются только тегами, и тысячи множеств тегов с одинаковой суммой и
   одинаковым XOR. Слабый хэш соберёт их в одну корзину, и решение не уложится
   во время.

## Требование для вашего языка

| Язык | Как это выглядит |
|---|---|
| C++ | `struct Item` + `operator==` + специализация `std::hash<Item>` (или свой функтор), контейнер `std::unordered_set<Item>` |
| Rust | Ручные `impl Hash` и `impl PartialEq, Eq` для `Item`, **без** `#[derive(Hash)]` на нём; контейнер `HashSet<Item>` |
| Zig | Свой контекст (`hash` + `eql`) для `std.HashMap`; память освобождается, `GeneralPurposeAllocator.deinit()` возвращает `.ok` |
| Go | Встроенный `map` не принимает свою хэш-функцию, поэтому хэш-таблица собирается вручную: `map[uint64][]Item`, где ключ — ваш хэш (можно на базе `hash/maphash`), а внутри корзины товары сравниваются вашей функцией `equal`. Удаление из корзины без утечек |
| Python | Класс с `__slots__`, `__eq__` и `__hash__`, контейнер `set`. Внутри `__hash__` **нельзя** вызывать `hash(frozenset(...))` и `hash(tuple(...))` от тегов: комбинирование хэшей тегов пишется самостоятельно |

## Вопросы на защите

1. Почему из `a == b` должно следовать `hash(a) == hash(b)`, а обратное не
   обязательно? Что сломается, если нарушить первое?
2. Почему XOR и сумма — плохие способы объединить хэши тегов? Чем лучше ваш
   способ?
3. Зачем приводить название к нижнему регистру **и** в хэше, **и** в
   сравнении, а не только в одном месте?
4. Устойчива ли хэш-таблица вашего языка к HashDoS (подбору входа, при
   котором все ключи падают в одну корзину)? Почему? Сравните с одним
   другим языком курса.
