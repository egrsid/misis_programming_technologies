# Склад с резервированием

Интернет-магазин продаёт один товар. Покупатель резервирует нужное количество,
затем подтверждает покупку или отменяет резерв. Реализуйте объект `Warehouse`,
который сохраняет корректное состояние при любой допустимой последовательности
команд. Тема: инкапсуляция и инварианты, слайды 26–40 лекции 3.

## Состояние

- `stock` — физический остаток на складе, включая зарезервированный товар;
- `reserved` — сумма количеств в активных резервах;
- `available = stock - reserved` — количество, доступное для новых резервов.

Всегда должно выполняться `0 ≤ reserved ≤ stock`. Изначально `stock = initial`,
резервов нет. Все количества целые; многопоточность в этой работе отсутствует.

## Команды

| Код | Метод | Успех | Отказ |
|---|---|---|---|
| `A` | `restock(count)` | Увеличить `stock` на `count` | `count ≤ 0` |
| `R` | `reserve(id, count)` | Создать активный резерв | `count ≤ 0`, недостаточно доступного товара или `id` уже использован |
| `C` | `confirm(id)` | Уменьшить `stock` и `reserved` на количество резерва; завершить резерв | Нет активного резерва с таким `id` |
| `X` | `cancel(id)` | Уменьшить `reserved`; завершить резерв | Нет активного резерва с таким `id` |
| `S` | `snapshot()` | Вернуть `[stock, reserved, available]` | Отказа не бывает |

**Отказ не меняет никакое состояние.** Неудачная попытка `R` не занимает
идентификатор. После успешного `R` идентификатор занят навсегда, в том числе
после `C` или `X`; повторный резерв с ним запрещён. Подтверждённый или
отменённый резерв нельзя завершить второй раз.

## Формат

Вход — один JSON-объект в stdin:

```json
{"initial":10,"ops":"RRXSRCSS","ids":[1,2,1,0,2,2,0,0],"counts":[7,4,0,0,4,0,0,0]}
```

`ops[i]`, `ids[i]`, `counts[i]` задают одну команду. Массивы имеют одинаковую
длину. Для `A` и `S` идентификатор игнорируется; для `C`, `X`, `S` количество
игнорируется. В игнорируемых полях тесты передают нули.

Выход — один JSON-объект:

```json
{"results":"+-+=++==","snapshots":[[10,0,10],[6,0,6],[6,0,6]]}
```

В `results` по символу на команду: `+` — успешное изменение, `-` — отказ,
`=` — снимок. В `snapshots` только результаты команд `S`, в порядке ввода.

В примере первый резерв занимает 7 единиц; второй отклоняется, поэтому `id=2`
остаётся свободным. После отмены первого резерва можно зарезервировать и
купить 4 единицы с `id=2`. Повторный снимок не меняет состояние.

Имена полей и коды операций во входе записаны буквальными ASCII-символами,
без escape-последовательностей. Пробелы и порядок полей могут быть любыми.

## Ограничения

| Параметр | Значение |
|---|---|
| Число команд | 0…100 000 |
| `initial` | 0…10⁹ |
| `id` | 0…10⁹ |
| `count` | −10⁹…10⁹ |
| Время без сборки | C++ / Rust / Zig — 2 с; Go — 3 с; Python — 5 с |
| Память | 256 МиБ |

Вход синтаксически корректен, коды известны, числовые значения находятся
в указанных границах. Отрицательные и нулевые количества — штатные отказы
операций. Накопленный остаток может превышать 32 бита: используйте 64-битные
целые. Ожидаемое время — O(n), память — O(n); снимок должен строиться за O(1).

## Требования к устройству решения

1. Остатки и резервы принадлежат `Warehouse`. Обработчик ввода вызывает его
   методы и не меняет поля самостоятельно.
2. Нет публичных `setStock`, `setReserved` и доступа к изменяемой таблице
   резервов. Снимок — значение, которое нельзя использовать для изменения склада.
3. Проверки и изменение состояния одной операции находятся внутри её метода.
   Ошибка не должна приводить к частичному списанию или занятию `id`.
4. Завершённые идентификаторы нужно помнить. Можно хранить статус резерва
   явно или использовать нулевое количество как признак завершения.

| Язык | Требование |
|---|---|
| C++23 | Класс с `private`-полями, публичные предметные методы, `snapshot() const` |
| Rust 1.97 | `Warehouse` в отдельном модуле с приватными полями; изменения через `&mut self`, снимок через `&self` |
| Zig 0.16 | Структура с методами. Изменять её поля только внутри реализации склада; это проверяется ревью, поскольку поля структуры не являются приватными. Освободить все выделения |
| Go 1.27 | Отдельный пакет `warehouse`, неэкспортируемые поля, методы изменения с получателем-указателем; снимок возвращается по значению |
| Python 3.12+ | Класс с внутренними полями по соглашению `_name`; методы возвращают `bool`, снимок — независимое значение. Не возвращать внутренний словарь |

Контейнеры стандартной библиотеки разрешены. Сам JSON-разбор уже дан в шаблоне.

## Защита

1. Назовите инвариант и докажите, что каждая успешная и неуспешная операция
   его сохраняет.
2. Почему приватные поля с безусловными сеттерами не решают задачу?
3. Где обеспечивается инкапсуляция компилятором, а где соглашением команды?
4. Как ваш код различает неизвестный, активный и завершённый резерв?
5. Почему после отмены и подтверждения получаются разные физические остатки?
