# Правила: публичный шаблон (`template_repo_url`)

Это то, что студент **форкает**. Правила оформления шаблона:

1. **Один каталог на язык**: `go/ python/ rust/ cpp/ zig/`. В форке студент
   правит только каталог своего языка; остальные можно оставить.
2. **Фиксированная точка входа** для каждого языка (Runner вызывает именно её):
   | Язык | Точка входа | Команда |
   |---|---|---|
   | Go | `go/` package `main` | `go run .` |
   | Python | `python/main.py` | `python main.py` |
   | Rust | `rust/` Cargo binary | `cargo run --locked --quiet` |
   | C++ | `cpp/CMakeLists.txt` target `solution` | CMake/Ninja → `/tmp/build/solution` |
   | Zig | `zig/build.zig` run-step | `zig build run` |
3. **Скелет уже реализует контракт** (читает JSON из stdin, пишет JSON в stdout),
   а собственно классификация помечена `TODO`. Так студент не борется с I/O, а
   решает задачу.
4. **Только stdlib** для I/O и JSON, где возможно (Python — `json`; Go —
   `encoding/json`; Rust — минимальный ручной парсер или разрешённый крейт,
   зафиксированный в `Cargo.lock`, т.к. запуск `--locked`; C++/Zig — простой
   парсер). Никакой сети/файлов.
5. **Открытые примеры для самопроверки** можно положить (напр. `examples.ndjson`
   с парой пар вход→ожидание), но они **не** являются основанием оценки —
   студент волен их изменить.
6. `README.md` шаблона = условие задачи ([TASK.md](../TASK.md)) + как запустить
   локально.

Скелеты пяти языков лежат рядом — берите как есть.
