# Вектор ресурсов

Заявка на запуск программы задаётся типом `Resources(cpu, ram, disk)`.
CPU измеряется в условных целых единицах, RAM и диск — в МиБ. Реализуйте
сложение, равенство, проверку вместимости и сравнение векторов.
Тема: пользовательские типы, операторы и частичный порядок, слайды 53–66
лекции 3.

## Семантика

Сложение покомпонентное:

```text
(1, 2, 3) + (4, 5, 6) = (5, 7, 9)
```

Вектор `a` помещается в `b` (`a ≤ b`), если **все три** его компоненты
не больше соответствующих компонент `b`.

| Результат сравнения | Условие |
|---|---|
| `equal` | Все компоненты равны |
| `less` | `a ≤ b` и `a ≠ b` |
| `greater` | `b ≤ a` и `a ≠ b` |
| `unordered` | В одной компоненте `a` меньше `b`, а в другой — больше |

Это **не лексикографическое сравнение**. Для строгого `less` достаточно,
чтобы хотя бы одна компонента была меньше, а остальные — не больше.
Для `unordered` все четыре операции `<`, `≤`, `>`, `≥` дают `false`,
но `a != b` даёт `true`.

## Формат

Вход — один JSON-объект в stdin:

```json
{"left":[[2,4,10],[2,8,10],[0,0,0],[4,8,10]],"right":[[4,8,10],[4,4,10],[0,0,0],[2,4,10]]}
```

Массивы имеют одинаковую длину. Каждая пара обрабатывается независимо.
Выход — JSON-массив объектов с суммой, результатом сравнения и признаком
вместимости **левого** вектора в **правый**:

```json
[
  {"sum":[6,12,20],"order":"less","fits":true},
  {"sum":[6,12,20],"order":"unordered","fits":false},
  {"sum":[0,0,0],"order":"equal","fits":true},
  {"sum":[6,12,20],"order":"greater","fits":false}
]
```

При передаче программе JSON может быть записан одной строкой. Порядок ключей
объекта и пробелы не влияют на проверку; порядок элементов массивов важен.

Имена полей и коды операций во входе записаны буквальными ASCII-символами,
без escape-последовательностей. Пробелы и порядок полей могут быть любыми.

## Ограничения

| Параметр | Значение |
|---|---|
| Число пар | 0…100 000 |
| Каждая компонента | 0…10¹² |
| Время без сборки | C++ / Rust / Zig — 2 с; Go — 3 с; Python — 5 с |
| Память | 256 МиБ |

Вход корректен. Все компоненты и их суммы помещаются в 64-битное целое.
Сложение возвращает новый вектор, исходные значения не меняются.
Время — O(n), дополнительная память на одну пару — O(1), без учёта
входных и выходных массивов.

## Требования для языков

| Язык | Реализация |
|---|---|
| C++23 | `Resources`, `operator+`, `operator==`, собственный `operator<=>` с `std::partial_ordering`; не `= default` для `<=>`, поскольку он сравнит поля лексикографически |
| Rust 1.97 | `Resources`, `Add`, `PartialEq` / `Eq`, собственный `PartialOrd`; `None` для несравнимой пары. Не реализовывать `Ord`, не выводить `PartialOrd` через derive |
| Zig 0.16 | `Resources`, методы `add`, `eql`, `compare`, `fits`; своё перечисление из четырёх результатов |
| Go 1.27 | Структура `Resources`, методы `Add`, `Equal`, `Compare`, `Fits`; именованный тип для результата сравнения |
| Python 3.12+ | Неизменяемый тип, например `@dataclass(frozen=True)`, `__add__`, `__eq__`, `__lt__`, `__le__`, `__gt__`, `__ge__`. Нельзя `order=True`: получится лексикографический порядок |

Для C++ / Rust / Python обработчик должен использовать реализованные
операторы. Для Go / Zig — соответствующие методы: имитировать синтаксис
перегрузки операторов не нужно. Нельзя реализовать `≤` как `not (a > b)`:
это неверно для несравнимых векторов.

В Python `NotImplemented` нужен для неподдерживаемого типа операнда;
несравнимые объекты самого типа `Resources` должны давать `False`
для операторов порядка.

## Защита

1. Чем частичный порядок отличается от полного? Приведите несравнимую пару.
2. Почему нельзя сравнивать сумму компонент или кортежи лексикографически?
3. Почему `not (a > b)` не равносильно `a ≤ b`?
4. Можно ли передать такое сравнение в обычную сортировку, которая ожидает
   строгий слабый порядок? Найдите три вектора, у которых несравнимость
   нетранзитивна.
5. Какие законы должны выполнять равенство, сложение и сравнение?

## Локальный запуск

Из выданного каталога решения:

```sh
./selfcheck.sh <cpp|rust|zig|go|python>
```

Поведение проверяется автоматически; использование собственного типа
и согласованность операторов — также на ревью.
