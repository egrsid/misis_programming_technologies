# Конвейер скидок

Магазин применяет к каждой цене последовательность скидок. Создайте разные
типы правил с общим интерфейсом `apply(price)` и используйте их в одном
конвейере. Тема: полиморфизм и сочетание ООП с чистыми функциями, слайды 22–23,
43–51 лекции 3.

## Правила

Все суммы заданы целым числом копеек. Правила применяются слева направо;
каждое получает результат предыдущего.

| Код | Параметры | Результат для текущей цены `p` |
|---|---|---|
| `F` | сумма `a` | `max(0, p − a)` |
| `P` | процент `a` | `floor(p × (100 − a) / 100)` |
| `T` | сумма `a`, порог `t` | Если `p ≥ t`, то `max(0, p − a)`, иначе `p` |

Округлять нужно **после каждого** процентного правила. Порог сравнивается
с текущей ценой, а не с исходной. Используйте целую арифметику, без `float`.
Пустой конвейер сохраняет цену. Исходные цены не изменяются; набор созданных
правил один и тот же для всех цен, включая повторяющиеся.

## Формат

Вход — один JSON-объект в stdin:

```json
{"prices":[1000,999,1000,0],"rules":"FP","amounts":[100,10],"thresholds":[0,0]}
```

`rules[i]`, `amounts[i]`, `thresholds[i]` описывают правило. Эти три
последовательности имеют одинаковую длину. Для `F` и `P` порог равен нулю
и игнорируется.

Выход — JSON-массив итоговых цен в исходном порядке:

```json
[810,809,810,0]
```

Если порядок правил поменять на `PF`, а суммы на `[10,100]`, результат:

```json
[800,799,800,0]
```

Пример с порогом:

```json
{"prices":[1000,1100],"rules":"FT","amounts":[100,200],"thresholds":[0,1000]}
```

```json
[900,800]
```

Имена полей и коды операций во входе записаны буквальными ASCII-символами,
без escape-последовательностей. Пробелы и порядок полей могут быть любыми.

## Ограничения

| Параметр | Значение |
|---|---|
| Число цен `n` | 0…1000 |
| Число правил `m` | 0…1000 |
| Цена, сумма `F` / `T`, порог | 0…10¹² |
| Процент `P` | 0…100 |
| Время без сборки | C++ / Rust / Zig — 2 с; Go — 3 с; Python — 5 с |
| Память | 256 МиБ |

Вход корректен, неизвестных кодов нет. Промежуточное произведение может
достигать 10¹⁴; оно помещается в 64-битное целое. Достаточно O(n·m) времени
и O(n + m) памяти.

## Главное требование

Нельзя свести всю задачу к `switch` / `match` / `if` по коду правила внутри
цикла обработки цен. После разбора входа должны существовать **разные типы
правил** с единым контрактом `apply(price) -> price`. Цикл конвейера вызывает
этот интерфейс и не знает формулы конкретного правила.

`apply` не меняет правило, не читает глобальное состояние и не выполняет
ввод-вывод. Повторный вызов с той же ценой даёт тот же ответ. Наследование
состояния и многоуровневые иерархии не нужны.

| Язык | Требование |
|---|---|
| C++23 | Абстрактный `Discount`, `virtual apply(...) const`, виртуальный деструктор, три производных класса с `override`; коллекция `std::unique_ptr<Discount>` |
| Rust 1.97 | Trait `Discount`, три структуры с реализациями, коллекция `Vec<Box<dyn Discount>>`; метод принимает `&self` |
| Zig 0.16 | Три структуры с `apply`, объединённые `union(enum)`. В его общем `apply` допустим `switch`, делегирующий вызов конкретному типу. Цикл конвейера работает только с общим методом |
| Go 1.27 | Интерфейс `Discount` с методом `Apply`, три структуры, коллекция `[]Discount`; без `type switch` в конвейере |
| Python 3.12+ | Три класса с общим `apply`; допустимы ABC, Protocol или duck typing. В конвейере нет `isinstance` и проверок имени класса |

Для Zig набор вариантов закрытый: новый тип потребует расширить union и его
диспетчеризацию. Это допустимо; сравните такой вариант с открытым интерфейсом
Go или trait-объектами Rust на защите. Ручная таблица виртуальных функций
не требуется.

## Защита

1. Добавьте правило «скидка на сумму, превышающую порог». Какие места
   пришлось изменить? Менялся ли сам цикл конвейера?
2. Покажите на примере, почему порядок и момент округления существенны.
3. Что делает `apply` чистой функцией? Почему он всё равно может быть методом?
4. Как выглядело бы решение на функциях или замыканиях? Где классы полезны,
   а где добавляют лишний код? Вторую полную реализацию писать не нужно.
5. Где в вашем языке происходит выбор конкретной реализации метода?

## Локальный запуск

Из выданного каталога решения:

```sh
./selfcheck.sh <cpp|rust|zig|go|python>
```

Автотесты проверяют формулы и порядок. Наличие полиморфизма и отсутствие
состояния между вызовами дополнительно проверяются ревью.
